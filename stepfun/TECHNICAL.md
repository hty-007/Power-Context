# 课页 · 技术说明

## 浏览器推理与模型

文档与查询都在浏览器的 Worker 内通过 Transformers.js 3.8.1 推理，输出经归一化的 512 维向量。应用优先显式选用 WebGPU，适配器缺失、模型初始化或推理失败时改用 WASM，并在页面显示后端和自动降级状态。WASM 在跨源隔离环境中使用 4 线程。下载模型后，浏览器只请求本机应用。实测阻断所有外部请求，两条路径均能完成导入和检索。

使用 BAAI BGE Small 中文 v1.5 的公开 ONNX 权重。在同一上游提交中分别取 FP32 与混合精度 FP16 文件，后者将模型大部分权重以半精度存储。下载脚本固定版本并核对 SHA-256。按「一个 ONNX 文件 + 共用配置及分词文件」统计，FP32 为 **95,292,085 B**，FP16 为 **47,937,635 B**，压缩 **1.99 倍**，减少 **49.7%**。[固定的 ONNX 版本及许可证](https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/7a21cfa835a0d8cba006e36210e7843b232a1107)

## seekdb 与会话

seekdb 1.4.0 保存知识库映射，每个知识库单独建集合，存向量、原文、标题、文档哈希和段号。通过 seekdb-js 1.4.0 配置 HNSW cosine 向量索引及 IK smart 全文索引，调用 seekdb 原生 `hybridSearch` 做两路召回和 RRF 排序（窗口 25，常数 20）。导入按内容哈希查重，每 24 段写入一批，所有批次写完刷新一次索引并按 ID 回查。浏览器记住选中的集合 ID，切换时重置查询及旧结果，Worker 复用已加载模型。

## 实测

Windows 11、i7-12700H、RTX 3060 Laptop、Edge 157.0.4341.46，数据库运行在同一设备。28 篇原创中文笔记和 28 条标注查询，配置各重复 3 次，表中为各阶段中位数。首次导入在新的浏览器上下文中完成。首次查询一列从导入完成后第一次调用检索开始计时，热查询采用各轮后续混合查询的中位数，再跨轮取中位数。

| 配置 | 本地权重传输 / 模型加载（ms） | 文档向量化（ms / 段每秒） | 写入 / 刷新 / 首次导入全程（ms） | 首查 / 热查全程（ms） | 热查推理 / seekdb（ms） |
| --- | ---: | ---: | ---: | ---: | ---: |
| FP32 · WASM · 批 8 | 567 / 1,894 | 1,741 / 16.1 | 80 / 516 / 4,384 | 74 / 45 | 18 / 16 |
| FP16 · WebGPU · 批 8 | 286 / 1,650 | 1,313 / 21.3 | 79 / 514 / 4,028 | 59 / 38 | 13 / 14 |
| FP16 · WASM · 批 8 | 281 / 1,493 | 2,156 / 13.0 | 80 / 516 / 4,356 | 70 / 54 | 29 / 14 |
| FP16 · WASM · 批 1 | 262 / 1,461 | 2,397 / 11.7 | 77 / 614 / 4,686 | 80 / 59 | 32 / 15 |

- 三个批 8 配置的混合检索 Recall@5 / MRR@5 / nDCG@5 均为 **0.982 / 0.964 / 0.960**，语义检索均为 **1.000 / 1.000 / 0.996**。Recall 按每条查询命中标注相关文档的比例求均值，nDCG 使用二值相关性。批 1 仅用前三条查询测延迟。
- 在 WASM 固定 FP16 条件下，批 8 使文档向量化耗时减少 **10.0%**。固定 WASM 和批 8 时，FP16 加载耗时减少 **21.2%**，文档推理耗时增加 **23.9%**。FP16 在 WebGPU 上比同精度 WASM 的批量推理快 **1.64 倍**。
- 界面另在刷新后的同一知识库测量提交表单到结果进入 DOM。冷查询 WebGPU **2,142 ms**、WASM **1,111 ms**，之后三次热查询的中位数分别为 **211 ms** 和 **60 ms**。首次部署另测 FP32 权重下载及校验 **64.43 s**，FP16 权重独立下载 **22.23 s**，两次网络时延为单次观测。表中本地传输计时含模型配置及分词文件，加载包含传输和会话初始化。
