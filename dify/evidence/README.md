# 验收步骤与记录

初始条件为刚启动的 Dify 1.14.2，已导入 `fog-harbor.yml`，PowerContext 1.4.1 由部署脚本启动。每次验收开新档即可获得独立初始状态。

| 步骤 | 操作 | 预期可见结果 |
| --- | --- | --- |
| 1 | 在 Dify 聊天页发送 `开始`，复制存档码 | 第一幕，显示修灯、问潮、送信。 |
| 2 | 发送 `修灯` | 第二幕，值班簿记下红色透镜，并开放引航。 |
| 3 | 点击新对话，发送 `继续 存档码` | 新对话显示已恢复，仍处于第二幕，保留透镜和引航行动。 |
| 4 | 发送 `放船`，再发送 `引航` | 放船提示缺少潮线，随后引航进入红光领航结局。 |
| 5 | 再开一档并选 `问潮`，在另一个新对话恢复新档，发送 `放船` | 值班簿显示潮线，进入潮线渡口结局。 |
| 6 | 新开一档并选 `送信`，在另一个新对话恢复，发送 `开闸` | 值班簿显示船闸急件，进入港灯接力结局。 |
| 7 | 开新档，选 `问潮` 后发送 `鸣铃` | 进入雾中候船结局，尾声保留与阿禾潮线有关的细节。 |
| 8 | 开新档后直接尝试 `引航` | 仍在第一幕，提示缺少线索。 |

验证进程重启时，在步骤 2 和 3 中间执行 `python run.py restart-memory`，等待 `python run.py status` 显示 `story-memory` 健康后再恢复。用 `python run.py logs` 对照同一 Artifact 的 `create`、`update` 和 `load`，可见修订从 1 到 3。

发布后，也可以在应用 **API 访问** 创建本地应用密钥，运行 `python verify.py`，在提示符输入密钥。脚本用新对话独立演练各条路线并把存档码脱敏，输出 `acceptance.local.json`。在全新部署的可丢弃环境可以运行 `python clean_acceptance.py` 自动初始化、导入、发布、重启存档服务并验收。
